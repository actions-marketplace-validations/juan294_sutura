# Sutura v0.2.1 evidence remediation plan

Date: 2026-09-01

Status: Local implementation and candidate verification complete; external gates not authorized

Integration branch: `develop`

Release branch: `main`

Target version: `0.2.1`

## Objective

Repair the product and evidence defects measured against immutable v0.2.0, publish v0.2.1 only after separate release authorization, and rerun the complete fixed-denominator evidence gates against one exact v0.2.1 candidate.

The v0.2.0 benchmark and matrices remain immutable failed baselines. No result, tag, artifact, or denominator is replaced.

## Measured defects

1. The pinned `ghcr.io/astral-sh/uv` digest returns HTTP 404 during ConTree import. All eight Python benchmark cases and both Python repair matrix cases stopped as infrastructure outcomes.
2. Repository-policy refusal ended as `gave-up` in both matrices instead of the expected safe `refused` terminal class.
3. One public audit-only case received an invalid diagnosis response and exited before it could write a terminal artifact.
4. The matrix workflow cannot upload a normal case artifact when an Action or audit process fails before the collector. Manual evidence recovery was required for three terminal attempts.
5. The v0.2 hidden-test score combines successful repair preservation with expected deceptive-patch rejection. It reports 0/15 when fourteen checks did not run and one deceptive patch correctly failed its hidden test.
6. The live quality targets were missed: repair 10/18, flake 9/10, and Tavily-grounded upstream repair 0/4.

## Design decisions

- Use a new immutable patch release. Never move or rewrite `v0.2.0`.
- Resolve a current Python image to an exact registry digest, then prove in ConTree that it contains Python, `uv`, Git, and tar before it becomes a runtime constant.
- Add an image-import availability canary to the candidate and release gates. An unavailable digest blocks publication before a benchmark dispatch.
- Keep policy denial distinct from search exhaustion. A policy-blocked candidate terminates as `refused` with the policy finding in evidence.
- Add a bounded provider schema retry only for a response that fails strict parsing. The retry keeps the same model, schema, token envelope, and total cost budget.
- Make matrix evidence upload unconditional after fixture identity exists. Early failure produces `infra-stop` with `costStatus: unavailable` when exact cost evidence does not exist. Zero observed cost is not presented as proven zero cost.
- Split hidden evidence into two measures: hidden repair preservation for selected repair candidates, and deceptive-patch rejection for supplied trap candidates. `not-run` remains explicit and cannot count as either success.
- Rerun the complete 51-case, 55-evaluation benchmark and both complete eight-case matrices. Targeted retries cannot replace the release gate.

## Verification

Each implementation phase runs its focused tests, `pnpm run typecheck`, `pnpm run lint`, `pnpm run build`, and the applicable release contracts. The exact final candidate runs `pnpm run ci:local` sequentially and exact-SHA CI before any paid or public action.

## Authorization gates

The plan does not authorize:

1. Provider or ConTree live canaries.
2. A new live benchmark or matrix spend cap.
3. Merge from `develop` to `main`.
4. npm publication, tag creation, Marketplace publication, or GitHub release creation.
5. Public demo enablement.

Each action needs its own exact candidate and explicit authorization.

## Exit gate

- The v0.2.1 candidate has a verified available Python image digest.
- JavaScript, TypeScript, and Python paths pass the complete local and live gates.
- Benchmark false approvals are zero.
- Hidden repair preservation and deceptive-patch rejection both pass their versioned gates with no hidden `not-run` result in the required denominator.
- Repair is at least 11/18, flaky accuracy is 10/10, and Tavily-grounded upstream repair is 4/4.
- Candidate and public matrices are 8/8 with zero false approvals.
- Every terminal failure path uploads a valid artifact without manual reconstruction.
- All public evidence binds to one exact v0.2.1 release commit.
- Verified work is integrated into local `develop`, and only task-owned worktrees and branches are removed.

The plan contains no unresolved questions.
