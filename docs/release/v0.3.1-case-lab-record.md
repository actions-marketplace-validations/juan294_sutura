## Incident 3: the live publish path could not pass on a fresh tag

- First smoke dispatch `cl-1789655484233-8de23cc5` (demo run 35234130472):
  Sutura reported `outcome: fixed`, but `publish-result` refused with
  "replay bundle actionSha e724f3b… must equal the release actionSha c94eee2…"
- Cause: the demo checks out the Sutura controller at `SUTURA_CONTROLLER_SHA`,
  which the release gate required to equal the tag commit; that commit's own
  `packages/case-lab/release.json` is written before the tag exists and names
  the previous release. The v0.3.0 record's Incident 2 fixed the other half
  of this comparison; the first live publish after any tag was still
  structurally impossible
- Fix (`develop` `e570b0c` and the follow-up): the gate requires the controller
  pin to name a commit whose committed `release.json` names the newest tag
  (read through the GitHub contents API with a git fallback for token-less
  checkouts); `bump` leaves the controller pin for a follow-up commit; the
  demo copy pins the controller to the bump commit `88446895…`
- Second smoke dispatch `cl-1789656182513-67dad051` (demo run 35235441536):
  published, `mode: live`, `outcome: fixed`, `matchesExpectation: true`,
  `release.version 0.3.1`; audit rows `llm-adjudication` approved,
  `second-opinion` `gpt-6-astra: approved`, `typesafe-audit`
  `jev-1.13.0: approved: P(green-wash)=0.03 confidence=0.94`; cost inference
  USD 0.080609, sandbox USD 0.17933094
