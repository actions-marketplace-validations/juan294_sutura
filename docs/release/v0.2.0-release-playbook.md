# Sutura v0.2.0 release playbook

This playbook separates local release proof from outward-facing authorization.
All evidence must bind to one exact 40-character release commit.

## Local candidate gate

1. Freeze one `develop` candidate and record its commit.
2. Run `pnpm install --frozen-lockfile`.
3. Run `pnpm run test:release-contracts`.
4. Run `pnpm run typecheck`, `pnpm run lint`, `pnpm run test`, and `pnpm run build`.
5. Run `git diff --exit-code -- packages/action/dist/index.cjs` after the Action build.
6. Run `node scripts/test-candidate-install.mjs <commit>`.
7. Run the eight external matrix cases sequentially and analyze them with
   `scripts/test-external-matrix.mjs`. Count only stages with a real sandbox
   operation ID. A failed or missing case stays in the denominator.
8. Create the release evidence manifest with `scripts/release-evidence.mjs`.
   Any pending required record means the release is not ready.

The v0.2.0 dogfood streak ran at Action commit
`a99e23199a80ae6ee51fe1680afb74188416160c`. The release evidence gate compares
the committed Git objects for both Action metadata files and the packaged Action
bundle with release commit `a943ded4c734aed75c5c63f2b2dd63a2f44556c2`.
It does not claim that the streak ran on the release commit.

The Phase 0 live controllers are resumable and fail closed:

- `pnpm placebo:live gate|streak|finalize` runs the canonical 51-case,
  55-evaluation benchmark with an append-only ledger and a hard reserve.
- `pnpm external-matrix:live gate|streak|finalize|cleanup` runs one exact
  allowlisted demo case per dispatch in separate candidate and public modes.
- Both controllers bind every result to the controller commit, release Action
  commit, package content hash, workflow run, artifact hash, and result hash.
- Paid streaks require literal `--authorize`, `--cap-usd`, and
  `--initial-reserve-usd`. A false approval stops the streak immediately.
- Matrix cleanup closes and deletes only resources recorded under the
  controller-owned `matrix/<controller-id>/<case-id>` and
  `sutura/fix-<run-id>` prefixes. It preserves public evidence artifacts and
  workflow runs.

Phase 0 owns `benchmark`, `candidate-matrix`, `dogfood`, `github-release`,
`local-gate`, `npm`, and `public-matrix`. The `demo`, `marketplace`, `feedback`,
and `devpost` records stay pending for their later roadmap phases. This means a
complete Phase 0 can still have a final-submission manifest with `ready: false`.

The candidate workflow is read-only and does not publish, push, tag, or spend
provider credit. It accepts only an exact commit.

## Phase 0 result

The complete v0.2.0 evidence program is terminal. The benchmark completed all
51 cases and 55 evaluations. The candidate and public matrices completed all
eight cases. All three results have zero false approvals, but they failed other
required safety and readiness gates. The exact evidence index is
`docs/demo/sutura-v0.2.0-phase-0-evidence.md`.

The public v0.2.0 Python image digest now returns HTTP 404 during ConTree
import. The release tag and package remain immutable. A new v0.2.1 candidate is
required; do not move `v0.2.0` or rewrite its evidence.

## Authorization-gated sequence

The following replacement-release work stays pending until it receives its own authorization:

- Implement and verify the reviewed v0.2.1 remediation plan.
- Run new provider and ConTree canaries against one exact candidate.
- Run the complete benchmark and candidate matrix under new exact caps.
- Merge the approved candidate to `main` and verify exact-commit CI.
- Publish npm, the Action tag, Marketplace listing, and GitHub release.
- Run `node scripts/test-public-install.mjs` against the new public package and tag.
- Run the separate public eight-case matrix. Candidate results cannot replace it.
- Update and enable the public demo, then run non-collaborator acceptance.
- Update the Devpost draft or submission with the final public evidence.

Publication uses npm trusted publishing. The release tag must equal the CLI
package version, the checked-in Action bundle must match source, and public
artifact verification must complete before evidence is declared final. A
failed public artifact matrix requires a new patch release.
